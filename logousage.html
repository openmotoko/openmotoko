Architektur-Übersicht Das System besteht aus drei klar getrennten Schichten. Backend: Agent Core (Node.js/TypeScript) Läuft als eigenständiger Prozess - auf dem lokalen Rechner, auf einem VPS, auf einer EC2-Instanz. Keine Annahmen über die Umgebung. Der Core ist die einzige Schicht die privilegierten Zugriff hat (Filesystem, Shell, Browser, Messaging-APIs). Intern besteht der Core aus: Gateway-Prozess der alle eingehenden Nachrichten normalisiert (egal ob von WhatsApp, Telegram, der Web-UI oder der Desktop-App) in ein einheitliches Message-Format Agent-Runtime die das LLM anspricht, Tool-Calls ausführt, und Ergebnisse zurückschreibt Skill-Runtime als isolierter Subprocess-Pool mit deklarativen Capability-Claims pro Skill Event-Bus der alle Agent-Aktionen als Stream verfügbar macht (für das Live-Activity-Feed in der UI) REST + WebSocket API über die sich alle Clients verbinden Die API ist das einzige Interface nach außen. Desktop-App, PWA und Messaging-Channels sind alle gleichwertige Clients dieser API. Frontend: Web-UI / PWA (React + Vite) Eine Single Page Application die sowohl als PWA im Browser läuft als auch als Basis für die Desktop-App dient. Mobile-first designed, Progressive Web App mit Offline-Capability für die Chat-History. Da die Web-UI gegen die Backend-API spricht, funktioniert sie identisch ob das Backend lokal oder auf einem VPS läuft. Man gibt beim ersten Start einfach die Backend-URL ein. Desktop-App (Tauri) Ein Tauri-Wrapper um die Web-UI mit drei zusätzlichen nativen Capabilities: Menubar-Icon mit Live-Status, System-Notifications, und automatischer lokaler Backend-Prozess-Verwaltung (starten, stoppen, updaten) ohne Terminal. Auf einem VPS braucht man Tauri nicht - da reicht die Web-UI im Browser. Tech Stack Entscheidungen und Begründungen Backend: Node.js + TypeScript + Fastify OpenClaw ist TypeScript, die Community und alle Skills sind TypeScript. Wir bleiben im gleichen Ökosystem um Kompatibilität zu ermöglichen und den bestehenden Skill-Korpus nicht auszuschließen. Fastify statt Express wegen Performance und nativer Schema-Validierung. Frontend: React + Vite + TailwindCSS + Radix UI Kein Next.js - wir brauchen kein SSR, und Next.js würde das Deployment auf einem einfachen VPS verkomplizieren. Vite als Build-Tool, Radix UI für accessible Komponenten ohne opinionated Styling, TailwindCSS für das Design-System. Die App ist vollständig statisch gebaut und kann von einem Nginx oder direkt aus dem Tauri-Binary ausgeliefert werden. Desktop: Tauri 2.0 Rust-basierter Native-Wrapper. Binary-Größe ~8MB statt ~150MB bei Electron. Wichtig weil wir wollen dass normale User das einfach herunterladen und es "einfach funktioniert". Datenbank: SQLite via Drizzle ORM Lokal-first. Keine externe Datenbank als Dependency. SQLite kann auf jedem VPS und jedem Laptop laufen. Drizzle gibt uns Type-Safety und Migrations. Alle Conversation-History, Skill-Configs, und Agent-Logs landen in einer einzigen .db-Datei die man einfach backupen kann. Messaging: Gleiche Channel-Abstraktion wie OpenClaw WhatsApp via Baileys, Telegram via grammy, Discord via discord.js, Signal via signal-cli Bridge, iMessage via BlueBubbles-Integration, Slack via Bolt. Jeder Channel ist ein separates Package mit einer gemeinsamen ChannelAdapter-Interface.
